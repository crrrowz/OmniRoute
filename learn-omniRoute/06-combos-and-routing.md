# 06 — الكومبو والتوجيه (Combos & Routing) 🎛️

> هذا أهم ملف بعد المزودين — هنا تصير قوة OmniRoute الحقيقية.

## 🎯 شنو هو الكومبو؟
**اسم واحد يمثل قائمة موديلات + طريقة اختيار بينهم (استراتيجية).**
أداتك تطلب `model: "my-combo"` وOmniRoute يقرر منو يخدم الطلب، وإذا فشل ينتقل للي بعده.

## 💡 ليش مفيد؟
- **ما يوگف شغلك أبداً** — 3–5 طبقات احتياطية.
- **تصرف بذكاء** — الاشتراك أولاً، الرخيص ثانياً، المجاني أخيراً.
- **تبدّل الموديلات بدون ما تلمس أدواتك** — الأداة تعرف بس اسم الكومبو.

---

## 1️⃣ أبسط طريقة: `auto` (بدون أي إعداد)

اكتب بأداتك `model: "auto"` وOmniRoute يقيّم كل مزود مربوط من 0 إلى 1 ويختار الأعلى.

| تريد… | استخدم | يركز على |
|------|-------|---------|
| الأفضل بشكل عام | `auto` | توازن (صحة 20%، حصة 15%، كلفة 15%…) |
| أفضل كود | `auto/coding` | ملاءمة المهمة 37% |
| أسرع رد | `auto/fast` | زمن الاستجابة 32% |
| الأرخص | `auto/cheap` | الكلفة 37% |
| الأذكى | `auto/smart` | الجودة + استكشاف 10% |
| الأكثر توفراً | `auto/offline` | الحصة المتبقية 37% |
| آخر مزود نجح | `auto/lkgp` | يثبت على آخر واحد اشتغل |

**كيف يتعلم:** يستخدم تاريخ الطلبات (زمن، أخطاء، نجاح). و5% من الطلبات يجرب بيها مزودين
ثانيين حتى يكتشف الأحسن (10% بـ `auto/smart`).

**الحماية الذاتية:** مزود تقييمه أقل من 0.2 ينستبعد 5 دقايق؛ إذا أكثر من نص المزودين واگعين
يوقف الاستكشاف؛ وإذا كلهم فشلوا يرجع لمزودين مجانيين مستقرين كحل أخير.

📍 **كتالوج Auto:** بصفحة Combos في كتالوج لأنواع auto، وكمان صفحة مستقلة
`/dashboard/auto-combo` (ما ظاهرة بالقائمة الجانبية — افتحها بالرابط مباشرة).
📚 **للتعمق:** `docs/getting-started/AUTO-COMBO-GUIDE.md` و `docs/routing/AUTO-COMBO.md`

## 2️⃣ كومبو يدوي (تحكم كامل)

📍 **وين:** القائمة الجانبية ← **OmniProxy** ← **Combos** — `/dashboard/combos`

🛠️ **شنو تسوي:**
1. **Create New** (أو اختر **قالب جاهز** من القوالب السريعة).
2. اكتب اسم (مثل `premium-coding`) — هذا اللي راح تكتبه بـ `model`.
3. اختر **الاستراتيجية** (الجدول تحت).
4. أضف خطوات: كل خطوة = **مزود + موديل + حساب محدد** (الـ builder المنظم).
   💡 تكدر تكرر نفس المزود بأكثر من خطوة بشرط اختلاف الموديل أو الحساب.
5. احفظ، وشوف **فحص الجاهزية** (readiness).
6. رتّب كروت الكومبو بالسحب — الترتيب ينحفظ.

### مثال 1: استغل اشتراكك ثم الرخيص
```
Name: premium-coding      Strategy: priority
  1. cc/claude-opus-4-7     ← اشتراك Claude
  2. glm/glm-4.7            ← احتياطي رخيص
  3. minimax/MiniMax-M2.7   ← أرخص
```

### مثال 2: صفر كلفة
```
Name: free-combo          Strategy: priority
  1. if/kimi-k2.7-code      ← Qoder مجاني
  2. kr/qwen3-coder-next    ← Kiro مجاني
```

### مثال 3: شغل 24/7 بدون انقطاع
```
Name: always-on
  1. cc/claude-opus-4-7
  2. cx/gpt-5.5
  3. glm/glm-4.7
  4. minimax/MiniMax-M2.1
  5. if/deepseek-v4-flash
```
(الأمثلة من `docs/guides/USER_GUIDE.md` — استبدل بالموديلات اللي فعلاً عندك.)

## 3️⃣ الاستراتيجيات (19 استراتيجية عامة)

| الاستراتيجية | شلون تشتغل | متى تستخدمها |
|-------------|-----------|-------------|
| **priority** | بالترتيب الصارم، الثاني بس إذا فشل الأول | أشهر وحدة: اشتراك ← رخيص ← مجاني |
| **fill-first** | يستهلك الأول لحد ما يخلص بعدين اللي بعده | تخلّص حصة قبل لا تنتقل |
| **weighted** | يوزع الترافيك بنسب (مثلاً 70/30) | توزيع مقصود |
| **round-robin** | بالدور (مع sticky limit) | توزيع الحمل بالتساوي |
| **random / strict-random** | عشوائي | توزيع بسيط |
| **p2c** | ياخذ 2 عشوائي ويختار الأصح بيهم | توزيع ذكي مع وعي بالصحة |
| **least-used** | الأقل استخداماً مؤخراً | توزيع متساوي |
| **cost-optimized** | الأرخص أولاً | توفير |
| **reset-aware / reset-window** | يفضل الحساب اللي حصته ترجع أقرب | عدة حسابات بحصص زمنية |
| **headroom** | حسب المساحة المتبقية من الحصة | — |
| **auto** | تقييم بالنقاط | ذكاء بدون إعداد |
| **lkgp** | آخر مزود ناجح | ثبات |
| **context-optimized** | الأكبر بنافذة سياق فارغة | محادثات طويلة |
| **cache-optimized** | يستفيد من الكاش | توفير |
| **context-relay** | لما يتبدل الحساب نص المحادثة، يولد ملخص وينقله للحساب الجديد | تبديل حسابات Codex بدون فقدان السياق |
| **fusion** | يرسل لعدة موديلات بالتوازي و"حَكَم" يدمج جواب واحد | جودة أعلى (كلفة أعلى ⚠️) |
| **pipeline** | سلسلة: مخرج موديل يدخل للثاني | معالجة بمراحل |

⚠️ **fusion** و**Chaos** يرسلون عدة طلبات = كلفة مضاعفة.

## 4️⃣ خيارات متقدمة داخل الكومبو

موجودة بصفحة تعديل الكومبو (`/dashboard/combos/<id>`):

| الخيار | الفائدة |
|-------|--------|
| **Timeouts** | أقصى وقت لكل هدف قبل الانتقال للي بعده |
| **Quota-only fallback** | ينتقل بس إذا السبب خلصان الحصة |
| **Reasoning token buffer** | مساحة إضافية لتوكنز التفكير |
| **Response validation** | يتحقق من الرد (وإذا خربان يجرب اللي بعده) |
| **Compression mode** | ضغط خاص بهذا الكومبو (Off/Lite/Standard/Aggressive/Ultra) |
| **System message templates** | رسالة نظام بيها `{{MODEL_ID}}` `{{PROVIDER_ID}}` `{{ACCOUNT}}` تتعبى تلقائياً |
| **Proxy assignment** | proxy خاص لأهداف الكومبو |

## 6️⃣ إعدادات التوجيه العامة

📍 **وين:** Configuration ← **Routing** — `/dashboard/settings/routing`

| الإعداد | مثال | الفائدة |
|--------|------|--------|
| **Model Aliases (wildcard)** | `claude-sonnet-*` → `cc/claude-sonnet-4-6` | أداة تطلب اسم قديم/عام، تحوله لموديلك |
| **Fallback Chains** | سلسلة احتياط عامة لكل الطلبات | أمان إضافي |
| **استراتيجية الحسابات** | Fill First، Round Robin، P2C، Random، Least Used، Cost Optimized | كيف يختار بين حسابات نفس المزود |
| **`fallbackDelayMs`** | تأخير قبل الانتقال | تهدئة |
| **Sticky sessions** | نفس الجلسة على نفس الحساب | استقرار الكاش والسياق |

💡 **Sticky من الأداة:** ارسل هيدر `X-Session-Id: اسم-الجلسة` حتى الجلسة تبقى على نفس الحساب.
